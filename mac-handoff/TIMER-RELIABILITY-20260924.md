# Timer reliability — 24 September 2026

Follow-on work on `codex/mac-handoff-20260923`.

- Session end now cancels pending notices instead of returning early with an undefined timer.
- Cancellation queries every pending infusion notice, including infusion indexes above nine and notices left by a previous process.
- Serialized notification mutations prevent delayed permission requests from resurrecting stopped timers. Failed/denied requests remain retryable on later synchronization; expired notices are skipped.
- A foreground countdown now persists completion at zero, triggering its existing chime/haptic path. Repeated recovery does not repeat the haptic for the same completion.

Validation: 28 brew-core tests; mobile TypeScript/Vite build; browser smoke at 390x844 including real five-second foreground completion, pause/relaunch, journal and import; Android debug build. No new dependencies, storage schema, package ID or signing key. iOS web assets are generated by `npm run cap:sync`; CocoaPods/Xcode remain a Mac task.

Remaining: observe native delivery while locked, in Doze and after ordinary process death. Force-stop is a separate condition and reliable delivery is not promised. These are best-effort notices, not guaranteed alarms. Test on Android 16 as well as the current Android 13 phone.
